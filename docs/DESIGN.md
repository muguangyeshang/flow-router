# 设计文档

本文写给想改匹配器或深度定制配置的人。每节末尾是"为什么这么设计"的生产依据。

## 1. 总体架构

```
查询 → cjk_bigrams 分词 → 五档加权打分（×idf）→ dominant 聚合
     → 双门判定（conf 门 + score 门）→ 命中 / 拒答（带 reason）
```

零模型、零网络、零第三方依赖。单次路由 O(词数 × 流程数)，实测 p50≈0.09ms。

## 2. 五档加权

| 档位 | 基准分 | 含义 |
|---|---|---|
| 触发词精确 | 34 | 多字触发词整串出现在查询里，或查询词与触发词逐字相等 |
| 流程名 | 30 | 查询词出现在流程名里 |
| 触发词包含 | 26 | 查询词是某触发词的子串（**已知缺陷源**，见 §5） |
| 说法表 | 24 | 口语模板整条命中（≥50% 两字组重叠，`ALIAS_SIM=0.5`） |
| 挂载技能 | 20 | 查询词命中挂载技能名 |
| 全文 | 10 | 查询词出现在流程 doc 正文 |

所有档位乘 BM25 风格 idf：`max(1, round(10·ln((N+1)/(df+0.5))))`，常见词自动降权。

**聚合用 dominant**：`max(pairs) + 0.3 × (sum(pairs) − max(pairs))`。不用 sum 是因为多词堆分会把 filler 查询抬过门；不用单 max 是因为多词一致命中确实是更强的信号。

## 3. 双门拒答

- **置信度门** `abstain_min`：`score / ideal < th` 拒。ideal 只统计"在任一流程语料里够得着"的词——把 filler 算进分母会造成长度偏置（大白话长句被系统性误拒）。
- **绝对分门** `score_min`：`score < sf` 拒。语料规模变化（加流程、加语料）会压低 idf，比值门拦不住绝对分数的塌陷。

**为什么两道都要**（生产实测）：只留比值门，"配置饮品"这类 filler 查询靠单点命中拿 0.39 的 conf 过门；只留绝对分门，29 个新技能进语料就把最紧正例从 +12 压到 −14。两道门的失效模式不重叠，这是留两道的原因。

## 4. 排除条款 not_for

单向匹配：只有**排除词出现在查询词里**（`n in t`）才打折（×0.35）。不做反向 `t in n`——"数据"会成为"数据库"的子串，反向会把所有含"数据"的合法爬虫查询误杀（实测"把这个网站的数据抓下来"被拒）。

`not_for` 解决的是匹配算法结构上做不到的事：阈值救不了"给数据库加索引优化查询"混进爬虫流程——因为"采集数据"是合法用法，不能禁掉"数据"。唯一出路是同句里的"索引/优化"主动排除。

## 5. 已知缺陷与实测走不通的修法

**触发词包含档的子串误伤**：日常词是专业词的子串就能拿 26 分（"会议室"⊂"会议纪要"）。生产库 20 道负对照里 6 个假接受全在这一档。

两条修法实测过、都走不通、**别再试第三次**：
1. 覆盖率硬门槛（<0.7 不给分）：假接受 6→0，但留出集 8/8→4/8——合法短查询一起死。
2. 按覆盖率打折：同样杀掉正例。根因是**正负两边的覆盖率是同一批数**，覆盖率这个特征本身分辨不了。

缓解手段是三件套：排除条款 + 双门 + 不可答样本压测。新流程上线前必须在 eval.json 里放不可答样本。

## 6. 语义方案的实测结论

在一个 2987 技能的生产系统上测过四轮 embedding 方案（bge-small-zh + MiniLM 双模型交叉）：
- 流程层正例：1/12 → 10/12，大胜
- 但 20 道冻结负对照假接受：6/20 → 10/20，翻倍
- 分数/margin 二维分不开负例（闲话 0.569 > 真需求 0.444）

结论：话题相关 ≠ 意图执行，语义层直接上会更坏。要加语义请走"语义提名 + 规则二段确认"并重测负对照。

## 7. 配置规范

`flows.json` 每个字段的责任边界：

| 字段 | 责任 | 约束 |
|---|---|---|
| `triggers` | 精确/包含档的唯一来源 | ≥3 个、不重复（lint 查）；与 `not_for` 互斥 |
| `alias` | 口语整句模板 | 不进 idf 语料；不与 triggers 重复；≥3 条 |
| `not_for` | 主动排除 | ≥2 字的词；不与 triggers 重叠 |
| `skills` | 挂载技能名（可选） | 仅作 20 分档信号，不参与执行 |
| `doc` | 全文语料 + idf 语料 | 必填；写清"管什么、不管什么" |
| `gate` | 双门阈值 | 用 calibrate 实测定，不拍 |
| `corpus_extra` | 追加 idf 语料（可选） | 放常见 filler 文本，压低 filler 权重 |

阈值纪律：**calibrate 出阈值 → holdout 冻结集验收 → 余量 <100 标脆弱**。改了配置/样本/语料三样中任何一样，前两步重跑。加新流程时先在 calibrate 样本里放它的正例、在 unanswerable 里放它的近义不可答。
